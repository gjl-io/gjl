## First public prerelease

Door runs a local Route switchboard, Gate provides an operator-run TLS
boundary, and Vault can broker credentials to paired relays. Route rules check
the original decoded request for blocks, then apply ordered replacements
before provider authentication. Route masking does not rewrite provider
response bodies delivered to clients; only a local recording copy can be
sanitized. The relay removes HTTP hop-by-hop headers when forwarding.

Desktop bundles include the matching `gjl` CLI and daemon. Desktop is
available for Windows x64, Linux x64/Arm64, and macOS Intel/Apple silicon.
Windows Arm64 has a standalone `gjl` only. See the
[installation and verification guide](https://github.com/gjl-io/gjl/blob/v0.0.1-alpha.1/docs/install.md)
for the asset matrix and first local Door setup.

This initial distribution is an **unsigned prerelease**. Its Windows and
macOS binaries lack platform-trusted publisher signatures, and macOS packages
are not notarized. There is no Windows MSIX; use the Windows ZIP or standalone
CLI. Verify the published SHA-256 checksums before use. macOS may require
Gatekeeper's per-item **Open Anyway** action.

### Alpha limits and data retention

- Use a fresh profile for each newer alpha. Earlier state is not automatically
  migrated or deleted; back up data you need before changing profiles.
- Traffic logging and masking audit are separate Route switches and default
  to off. Enabled local body records remain until explicit deletion. Saved
  exports have their own retention.
- Binary and uninspectable protocol payloads are not body-masked. Review the
  [Route replacement guide](https://github.com/gjl-io/gjl/blob/v0.0.1-alpha.1/README.md#using-route-replacements)
  before depending on a rule.
- Updates are advisory only. gjl does not automatically download or
  install them.
